TRANSFORMATION ANALYSIS
================================================================================

The coordinate systems are NOT simply offset - there's a complex transformation:

1. ROTATION: ~90 degrees
   - Detection X+ roughly corresponds to Robot Y-
   - Detection Y+ roughly corresponds to Robot X+

2. SLIGHT SKEW/DISTORTION:
   - The workspace is not perfectly rectangular in robot space
   - Small non-linearities exist

3. SCALE VARIATION:
   - Detection X: 0->300 (range of 300)
   - Robot X: 85.1->385.8 (range of ~300.7)
   - Robot Y: 12.2->314.5 (range of ~302.3)

4. TRANSLATION/OFFSET:
   - Detection (0,0) is NOT at Robot (0,0)
   - There's an ~89mm X offset and ~312mm Y offset at the origin

================================================================================
WHY SIMPLE OFFSETS DON'T WORK
================================================================================

Your current code uses:
  robot_x = detection_x + offset_x
  robot_y = detection_y + offset_y

This assumes:
  - NO rotation
  - NO scaling
  - Only translation

But the actual transformation includes:
  ✗ ~90 degree rotation
  ✗ Slight scale differences
  ✗ Non-linear distortion
  ✗ Complex offset

This is why the robot doesn't align with clicked targets!

================================================================================
SOLUTION: USE HOMOGRAPHY TRANSFORMATION
================================================================================

A homography matrix can handle:
  ✓ Rotation
  ✓ Scaling
  ✓ Translation
  ✓ Perspective distortion

The transformation should be:
  [robot_x]   [h11 h12 h13]   [det_x]
  [robot_y] = [h21 h22 h23] × [det_y]
  [   1   ]   [h31 h32 h33]   [  1  ]

Using the 4 calibration points, OpenCV's cv2.findHomography() can calculate
the exact transformation matrix needed.
